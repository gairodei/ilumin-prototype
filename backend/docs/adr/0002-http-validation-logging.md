# ADR 0002: Fastify, zod and structured logging

- Status: Accepted for Stage 1A

## Decision

- **HTTP: Fastify 5.** It is stable and well-typed, with built-in pino logging, server-generated request IDs, body limits, `return503OnClosing` and graceful `close()`.
- **Validation: zod 4.** It handles both configuration and request input. Bodies are `strict` objects: unknown fields are refused, not ignored. Failures return `400 VALIDATION_FAILED` with `details[].path` (`body.email`, `params.userId`).
- **Pipeline order** (`src/app/route.ts`):
  1. Authenticate. This happens in `onRequest`, before the body is parsed.
  2. Validate params and query.
  3. Authorise. Refusals are audited.
  4. Validate the body.
  5. Open a transaction and claim idempotency.
  6. Run the handler.
  7. Commit.
- **Errors**: every error is `{ "error": { "code", "message", "requestId", "details"? } }`. Unexpected errors are `500 INTERNAL` with no internal detail. JSON only: `text/plain` is unregistered, so it returns 415. Oversized bodies return 413.
- **Request IDs**: request IDs are always generated by the server (UUID), and `X-Request-Id` is returned. A safe client `X-Correlation-Id` is kept as the correlation ID; otherwise the request ID is used.
- **Logging**: one JSON line per request, with the request ID, correlation ID, method, route pattern, path without the query string, status, duration and user ID. No headers, bodies, tokens, emails or names are logged. Redaction paths are a second layer. Token rejections log only a reason code.
- **CORS**: CORS is off unless `CORS_ALLOWED_ORIGINS` lists exact origins. Wildcards are refused, `http` origins are refused in production, and credentials are off (bearer tokens, no cookies).

## Consequences

- Every route uses `defineRoute` (protected) or `definePublicRoute` (health only). See ADR 0005.
