# Provisional Decisions Register: client clarifications R1–R5 (Oct 2026)

These are decisions made only so the offline prototype can be used interactively. None of them is a confirmed client rule. Each entry gives the current behaviour, the reason for it, where it lives in the code, and what to change once the client confirms. Unresolved client questions are listed at the end.

Status values:
- **Provisional:** built and working, awaiting confirmation.
- **Open:** nothing has been built, because building it would mean inventing a rule.

## P-31: what is confirmed and what stays open

- **Confirmed, no longer labelled pending for Level 3:**
  - A Level 3 learner's delivery mode comes from the fee option they choose.
  - A batch can contain Self-Paced and Fully Assisted learners.
  - The Level 3 wizard and each Level 3 programme's Support tab state this. The remaining programme setting is described only as the **default class pattern for new batches**.
- **Still open (P-31 tag kept):**
  - What exactly defines Fully Assisted and Self-Paced (the support each includes).
  - How modes work for Level 2, 4 and 5.
  - Observation fees still follow the programme's Support type (CH-38, transitional until N5).

## Open client decisions (nothing invented)

- Is any Pass or Fail ever automatic? None is built.
- Can a learner resubmit after a Fail? How many times, and do the attempt limits apply?
- Must the Assessor agree with the Coordinator's criterion judgements, override them, or neither? Which judgement counts when they differ?
- Can a Coordinator verify or lock evidence?
- Does Pass mean "Completed"? What status follows a Fail? Can Pass be declared while answers are Added to PD or Partially Met?
- When and how is the outcome shown to the learner? Does it go through the Coordinator release, and what can the agency see?
- Can the Super Admin declare or override an outcome?
- Should existing "Completed" records get a declared outcome, and from what evidence?
- Fee options: should options have their own deposit or instalments? Can a learner change their option before paying? Should existing learners be mapped to new options?
- Session entitlements per fee option or mode (number of classes, attendance rules) are not defined. None is built.
- Batch eligibility (admission / enrolment / payment) when adding learners is still open (S5e).
- Should assignments published before a learner joins be copied to them (PD-R5-03)?
- Should new sessions and weekly plans start with every active fee option ticked, or with nothing ticked (PD-R2-08, PD-R2-13)?
- The Level 3 observation-fee rate still comes from the programme's stored support value until learner-level fees exist (PD-R2-12).
- The Coordinator's timeline editor changes dates only and has no audience selector. Audiences are set in the batch Schedule area by staff with the existing scheduling rights (PD-R2-16, PD-R2-17).
